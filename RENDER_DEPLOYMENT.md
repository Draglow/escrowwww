# Render Deployment Guide

This guide will help you deploy the Crypto Escrow Platform to Render.com.

## Prerequisites

1. **Render Account**: Sign up at [render.com](https://render.com)
2. **GitHub Repository**: Your code should be in a GitHub repository
3. **Required API Keys**:
   - TronGrid API Key (get from [trongrid.io](https://www.trongrid.io/))
   - Telegram Bot Token (create via [@BotFather](https://t.me/botfather))

## Deployment Options

### Option 1: Blueprint Deployment (Recommended)

This method deploys all services at once using the `render.yaml` file.

1. **Connect Repository**:
   - Go to [Render Dashboard](https://dashboard.render.com/)
   - Click "New" → "Blueprint"
   - Connect your GitHub repository
   - Render will detect the `render.yaml` file

2. **Configure Environment Variables**:
   
   After blueprint is detected, you'll need to set these **sync: false** variables:

   **Backend Service (`escrow-backend`)**:
   ```
   ALLOWED_HOSTS=your-backend-url.onrender.com,your-frontend-url.onrender.com
   CORS_ALLOWED_ORIGINS=https://your-frontend-url.onrender.com
   TRONGRID_API_KEY=your-trongrid-api-key
   TELEGRAM_BOT_TOKEN=your-telegram-bot-token
   WEBAUTHN_RP_ID=your-frontend-url.onrender.com
   WEBAUTHN_ALLOWED_ORIGINS=https://your-frontend-url.onrender.com
   FRONTEND_URL=https://your-frontend-url.onrender.com
   ```

   **Frontend Service (`escrow-frontend`)**:
   ```
   NEXT_PUBLIC_API_URL=https://your-backend-url.onrender.com
   NEXT_PUBLIC_WS_URL=wss://your-backend-url.onrender.com
   NEXT_PUBLIC_TELEGRAM_BOT_NAME=your_bot_name
   NEXT_PUBLIC_APP_URL=https://your-frontend-url.onrender.com
   NEXT_PUBLIC_WEBAUTHN_RP_ID=your-frontend-url.onrender.com
   ```

   **Celery Worker (`escrow-celery-worker`)**:
   ```
   TRONGRID_API_KEY=your-trongrid-api-key
   TELEGRAM_BOT_TOKEN=your-telegram-bot-token
   ```

3. **Deploy**:
   - Click "Apply" to create all services
   - Render will automatically:
     - Create PostgreSQL database
     - Create Redis instance
     - Deploy backend API
     - Deploy Celery workers
     - Deploy frontend

### Option 2: Manual Service Creation

If you prefer to create services individually:

#### 1. Create PostgreSQL Database

```
Name: escrow-postgres
Plan: Starter ($7/month)
Database Name: escrow_db
User: escrow_user
```

#### 2. Create Redis Instance

```
Name: escrow-redis
Plan: Starter ($10/month)
Maxmemory Policy: allkeys-lru
```

#### 3. Create Backend Web Service

```
Name: escrow-backend
Environment: Python
Build Command:
  cd backend && pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate

Start Command:
  cd backend && daphne -b 0.0.0.0 -p $PORT config.asgi:application

Health Check Path: /api/v1/health/
```

**Environment Variables**:
```bash
# Auto-generated
SECRET_KEY=<auto-generated>
WALLET_ENCRYPTION_KEY=<auto-generated>

# From Database
DATABASE_URL=<from escrow-postgres>
REDIS_URL=<from escrow-redis>
CELERY_BROKER_URL=<from escrow-redis>
CELERY_RESULT_BACKEND=<from escrow-redis>

# Manual Configuration
DEBUG=False
ALLOWED_HOSTS=escrow-backend.onrender.com,escrow-frontend.onrender.com
CORS_ALLOWED_ORIGINS=https://escrow-frontend.onrender.com
TRON_NETWORK=mainnet
TRONGRID_API_KEY=your-api-key
TELEGRAM_BOT_TOKEN=your-bot-token
PLATFORM_FEE_PERCENTAGE=2.5
MIN_DEAL_AMOUNT=10.00
MAX_DEAL_AMOUNT=100000.00
WEBAUTHN_RP_ID=escrow-frontend.onrender.com
WEBAUTHN_RP_NAME=Escrow Platform
WEBAUTHN_ALLOWED_ORIGINS=https://escrow-frontend.onrender.com
FRONTEND_URL=https://escrow-frontend.onrender.com
```

#### 4. Create Celery Worker

```
Name: escrow-celery-worker
Environment: Python
Build Command:
  cd backend && pip install -r requirements.txt

Start Command:
  cd backend && celery -A config worker -l info
```

**Environment Variables**: Same as backend, plus:
```bash
TRONGRID_API_KEY=your-api-key
TELEGRAM_BOT_TOKEN=your-bot-token
```

#### 5. Create Celery Beat (Optional - for scheduled tasks)

```
Name: escrow-celery-beat
Environment: Python
Build Command:
  cd backend && pip install -r requirements.txt

Start Command:
  cd backend && celery -A config beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler
```

#### 6. Create Frontend Web Service

```
Name: escrow-frontend
Environment: Node
Build Command:
  cd frontend && npm install && npm run build

Start Command:
  cd frontend && npm start
```

**Environment Variables**:
```bash
NODE_VERSION=18.17.0
NEXT_PUBLIC_API_URL=https://escrow-backend.onrender.com
NEXT_PUBLIC_WS_URL=wss://escrow-backend.onrender.com
NEXT_PUBLIC_TELEGRAM_BOT_NAME=your_bot_name
NEXT_PUBLIC_APP_NAME=CryptoEscrow
NEXT_PUBLIC_APP_URL=https://escrow-frontend.onrender.com
NEXT_PUBLIC_WEBAUTHN_RP_ID=escrow-frontend.onrender.com
NEXT_PUBLIC_ENABLE_ANALYTICS=false
NEXT_PUBLIC_ENABLE_SENTRY=false
```

## Post-Deployment Steps

### 1. Create Django Superuser

Connect to your backend shell:
```bash
# In Render Dashboard → escrow-backend → Shell
cd backend
python manage.py createsuperuser
```

### 2. Configure Telegram Bot Webhook (Optional)

If using Telegram bot features:
```bash
curl -X POST "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setWebhook?url=https://your-backend-url.onrender.com/api/v1/telegram/webhook/"
```

### 3. Test the Deployment

1. **Backend Health Check**:
   ```
   https://your-backend-url.onrender.com/api/v1/health/
   ```

2. **Frontend**:
   ```
   https://your-frontend-url.onrender.com
   ```

3. **Admin Panel**:
   ```
   https://your-backend-url.onrender.com/admin/
   ```

### 4. Configure Custom Domain (Optional)

1. Go to your service settings
2. Click "Custom Domain"
3. Add your domain (e.g., `api.yourdomain.com` for backend)
4. Update DNS records as instructed
5. Update environment variables with new domain

## Important Security Notes

### 1. Generate Strong Keys

For `WALLET_ENCRYPTION_KEY`, generate a secure Fernet key:
```python
from cryptography.fernet import Fernet
print(Fernet.generate_key().decode())
```

For `SECRET_KEY`, use Django's generator:
```python
from django.core.management.utils import get_random_secret_key
print(get_random_secret_key())
```

### 2. HTTPS Only

Render provides free SSL certificates. Ensure:
- All URLs use `https://` and `wss://`
- `SECURE_SSL_REDIRECT=True` in production
- Update CORS and ALLOWED_HOSTS accordingly

### 3. Environment Variables

Never commit sensitive values to Git. Use Render's environment variable management.

## Monitoring & Maintenance

### View Logs

```
Render Dashboard → Service → Logs
```

### Database Backups

Render automatically backs up PostgreSQL databases. To create manual backup:
```
Render Dashboard → escrow-postgres → Backups → Create Backup
```

### Scaling

To handle more traffic:
1. Upgrade service plans (Starter → Standard → Pro)
2. Add more Celery workers
3. Enable autoscaling (available on Pro plans)

## Troubleshooting

### Build Failures

**Issue**: Python dependencies fail to install
```bash
# Solution: Check requirements.txt for version conflicts
# Try pinning specific versions
```

**Issue**: Static files not collected
```bash
# Solution: Ensure STATIC_ROOT is set in settings.py
# Check build command includes collectstatic
```

### Runtime Errors

**Issue**: Database connection errors
```bash
# Solution: Verify DATABASE_URL is correctly set
# Check PostgreSQL service is running
```

**Issue**: Redis connection errors
```bash
# Solution: Verify REDIS_URL is correctly set
# Check Redis service is running
```

**Issue**: WebSocket connections fail
```bash
# Solution: Ensure using wss:// (not ws://)
# Check CORS and ALLOWED_HOSTS include frontend domain
```

### Performance Issues

**Issue**: Slow response times
```bash
# Solutions:
# 1. Upgrade to higher plan
# 2. Enable database connection pooling
# 3. Add Redis caching
# 4. Optimize database queries
```

- Celery Beat: $7/month

### Free Tier Option

Render offers free tier for web services (with limitations):
- Services spin down after 15 minutes of inactivity
- 750 hours/month free
- Not suitable for production

## Continuous Deployment

Render automatically deploys when you push to your repository:

1. **Auto-Deploy**: Enabled by default
2. **Branch**: Configure which branch to deploy (main/production)
3. **Deploy Hooks**: Use webhooks for manual triggers
